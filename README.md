# 简扫 JiScan

一款极简、**完全离线**的安卓文档扫描 App。只做一件事：把纸质文件快速扫成干净的 PDF/图片。

> 命名规则：`YYMMDD+[部门]+[签名]+事由`，例如 `260424_XX部门_Almighty119_合同`。
> 无网络、无账号、无广告、无水印、无追踪。

## 功能一览

### 扫描页（三栏之「扫描」）
- 相机**在 App 内直接打开**，不跳转系统相机；拍照后自动框选文档并校正。
- 顶部：重拍 / 导入 / 保存 N 页。
- 中央：相机预览 + 右侧「上一页」缩略图。
- 功能矩阵一屏展示，不翻页：
  - **模式**：文档 / 书本 / 证件
  - **矫正**：自动 / 手动 / 曲线（后两者进入可拖四角的框选页）
  - **滤镜**：彩色 / 黑白（Otsu 自动阈值）
  - **灯光**：自动 / 长开 / 长闭
  - **参考线**：九宫格 / 十字线 / 无
  - **去阴影**：开 / 关（局部亮度归一化，消除折痕阴影）
- 多页连拍，页序可调整。

### 文档页（三栏之「文档」）
- 顶部显示文档数，卡片网格预览。
- **文档整理**：勾选多个文档→合并；点单个卡片→拆分（指定前 N 页保留，其余另存新文档）。
- 文档内可：补充扫描页 / 导出 PDF / 导出图片到相册 / 系统分享 / 重命名（部门·签名·事由）/ 删除文档。
- 每页可：上移 / 下移改变顺序 / **清除手写** / OCR / 存相册 / 删除。

### 设置页（三栏之「设置」）
- 签名、单位部门填写并保存；展示命名规则与示例。
- 隐私与安全承诺、OCR 语言状态、关于信息。

## 安全与纯净性

将军最看重这条，我把话说透：

1. **没有网络权限，物理上无法联网**
   - `AndroidManifest.xml` 里显式移除了 `android.permission.INTERNET` 和 `ACCESS_NETWORK_STATE`（用 `tools:node="remove"` 强制剔除依赖库可能夹带的联网权限）。
   - 全部代码里没有任何 HTTP/网络请求逻辑；OCR 用的是内置离线模型。
   - 安装后可在手机「设置 → 应用 → 简扫 → 权限」里核实：只有「相机」一项。

2. **数据不出手机**
   - 所有文件存在应用私有目录，别的 App 读不到。
   - 备份和云同步全部关闭（`allowBackup=false` + `dataExtractionRules` 全部排除）。

3. **依赖干净、来源可查**
   - 只有 4 类依赖：Jetpack Compose/UI（Google 官方）、CameraX（Google 官方）、Tesseract4Android（开源 Apache-2.0）、Kotlin 协程（JetBrains 官方）。
   - **没有**任何广告 SDK、统计 SDK、推送 SDK、崩溃上报 SDK、第三方埋点。
   - 中文 OCR 语言包在编译时从 Tesseract 官方仓库（`tesseract-ocr/tessdata_fast`）下载并打进 APK，运行时不联网下载任何东西。

4. **代码开源可审计**
   - 全部源码就是你这个文件夹里的 `.kt` 文件，任何人都能逐行读。
   - APK 由 GitHub 官方云服务器用官方工具链编译，不是我本地塞给你的黑盒安装包。

5. **自己复核的办法（建议做一次）**
   - 装一个杀毒/安全软件（如手机自带的安全中心）扫一下 APK，会显示无风险。
   - 上传到 VirusTotal（virustotal.com）在线扫描——这是全球 70+ 家杀毒引擎联合检测，最权威。把 APK 传上去，正常应为 0 报毒。
   - 在手机设置里查看权限，确认只有相机。
   - 断网状态下打开 App 扫描一次，能正常工作，即证明不依赖网络。

> 说明：因为 APK 没有上架应用商店、也没有购买商业签名证书，用的是编译时的调试签名，首次安装时手机会提示「未知来源应用」——这是正常的，不是病毒提示。

## 零基础：从 GitHub 做出 APK 并安装

你已登录 GitHub，但没做过项目。跟着下面一步步来，全程在网页上操作，**不用装任何软件**。

### 准备：先把项目文件打包好

项目文件夹叫 `jiscan`，我已经把它打包成了 `简扫JiScan-项目源码.zip`。解压后得到 `jiscan` 文件夹，里面就是全部源码。等下要把这个**文件夹里的东西**上传到 GitHub。

### 第 1 步：新建一个仓库（repository）

1. 打开 GitHub 网站并登录。
2. 点页面右上角的 **「+」** 号 → 选 **「New repository」**。
3. 填写：
   - **Repository name**（仓库名）：填 `jiscan`（只能用英文、数字、横线）。
   - **Description**（描述）：可不填。
   - 选 **Public**（公开）。不要用 Private——GitHub 免费版的 Actions 在私有仓库有额度限制，公开仓库免费 unlimited。
   - **不要**勾选 "Add a README file"、".gitignore"、"license" 这三个选项，保持仓库完全空白。
4. 点绿色按钮 **「Create repository」**。

### 第 2 步：上传文件（关键，注意隐藏文件夹）

创建成功后会出现一个页面，中间有提示文字 "…or push an existing repository from the command line"，上面还有一行小字 **"uploading an existing file"**（上传已有文件）。

1. 点 **"uploading an existing file"** 这个链接。
2. 进入上传页面后，打开你解压出来的 `jiscan` 文件夹，**选中里面的全部文件**（Ctrl+A），直接拖到网页的上传区域。
3. ⚠️ **特别注意隐藏文件夹 `.github`**：
   - `.github` 是隐藏文件夹，Windows 资源管理器默认不显示。
   - 先在资源管理器顶部「查看」菜单勾选 **「隐藏的项目」**，就能看到 `.github` 了。
   - 必须把 `.github` 文件夹也一起上传——里面装着自动编译的配置 `workflows/build.yml`。**漏了它就不会自动编译。**
   - 拖拽时建议连 `.github` 文件夹整个拖进去；网页会保留文件夹结构。
4. 确认上传列表里能看到：`.github`、`app`、`gradle` 三个文件夹，以及 `build.gradle.kts`、`settings.gradle.kts`、`gradle.properties`、`README.md`、`.gitignore` 这些文件。
5. 页面底部点 **「Commit changes」**（提交更改）。

> 如果拖拽后 `.github` 没进去（GitHub 网页端有时会忽略隐藏文件夹），用这个备用办法：
> 上传完其他文件后，在仓库页面点「Add file」→「Create new file」，在文件名框里输入 `.github/workflows/build.yml`（斜杠会自动创建文件夹），然后把项目里 `build.yml` 文件的内容复制粘贴进去，点 Commit。

### 第 3 步：触发自动编译

1. 上传完成后，点仓库顶部的 **「Actions」** 标签。
2. 第一次进来，左侧会显示工作流名称 **「Build JiScan APK」**，右侧可能出现一个提示 "Workflows aren't being run on this fork" 或要求启用——若有绿色按钮 **「I understand my workflows, go ahead and enable them」**，点它启用。
3. 现在点左侧的 **「Build JiScan APK」**，再点右侧的 **「Run workflow」** → 下拉里再点一次绿色 **「Run workflow」** 按钮，手动触发一次编译。
   - （其实第 2 步提交文件时也会自动触发一次，这里手动触发是为了确保开始。）
4. 页面会列出一次正在运行的任务，点进去能看到实时日志。第一次编译要下载依赖，通常需要 **5–15 分钟**，请耐心等。
5. 等它跑完：
   - ✅ **绿色对勾** = 编译成功。
   - ❌ **红色叉** = 失败。点进去拉到最下面看红色报错。最常见是下载中文语言包时网络抖动——点右上角 **「Re-run all jobs」** 重试即可。

### 第 4 步：下载 APK

1. 编译成功的页面往下拉，找到 **「Artifacts」** 区域，会有一个叫 **「JiScan-APK」** 的条目。
2. 点它，会下载一个 zip 包。
3. 解压这个 zip，里面就是 `JiScan-YYMMDD.apk`（YYMMDD 是编译当天日期，如 `JiScan-261124.apk`）。

> 注意：Artifacts 下载有时需要登录 GitHub，你已经登录了，没问题。artifact 默认保留 90 天，请及时下载。

### 第 5 步：安装到手机

1. 把 APK 文件传到手机（微信文件传输助手、QQ、数据线都行）。
2. 在手机上点开这个 APK。
3. 系统提示「未知来源应用」→ 选择允许/仍然安装（原因见上面安全章节第 5 条说明）。
4. 安装完成，打开 App，授予**相机权限**（这是它唯一申请的权限）。
5. 建议按安全章节第 5 条做一次断网测试。

### 以后想改东西怎么办

- 在手机上用出毛病 → 把现象告诉我，我改好源码 → 你把这个文件重新上传到 GitHub（覆盖旧文件）→ Actions 自动重新编译 → 下载新 APK 重装。
- 每次重新上传后，Actions 都会自动跑，不用再手动点 Run workflow。

## 怎么用

**扫描流程**
1. 打开 App 停在「扫描」页，顶部选模式（文档/书本/证件）。
2. 底部选矫正方式（自动最快；纸张弯曲用手动或曲线）、滤镜、灯光、参考线、去阴影。
3. 对准文档，中间圆形按钮拍照。自动模式直接框选校正；手动/曲线模式会进入四角调整页，拖好点对勾。
4. 可连续拍多页，右上角显示"保存 N 页"。右侧小窗是刚拍的上一页。
5. 点顶部「保存N页」完成，文件名按 `YYMMDD_部门_签名_事由` 生成。

**文档管理**
- 「文档」页点某个文档进入：可补充扫描页、导出 PDF、导出图片、系统分享。
- 每页有 ↑↓ 箭头调整顺序，铅笔图标清除手写，放大镜图标 OCR。
- 返回文档列表，点「文档整理」：勾选多个可合并，点单个卡片可拆分。

**设置**
- 填签名和单位部门并保存，之后新文档会按此命名。

## 畸变/折痕/缺角纸张怎么处理

针对你提到的"纸张畸变、多个不规则曲线、折痕、缺失"，App 里已经做了这些对策：

| 问题 | App 的对策 | 你要做的 |
|---|---|---|
| 纸张弯曲/翘起 | 「矫正 → 曲线」+「去阴影 开」；边缘检测改为多点采样，容忍弧形边 | 尽量压平拍摄；弯曲明显时选曲线模式 |
| 折痕阴影 | 「去阴影」用局部亮度归一化，压平明暗不均 | 拍摄时避免斜射强光 |
| 缺角 | 边缘检测用鲁棒百分位，缺一小角不影响整体框选；四角内缩避免把桌面框进去 | 缺角较大时用手动模式拖动四角 |
| 背景与纸同色、检测失败 | 自动检测会回退到整图，不会崩 | 换深色/对比背景，或用手动模式 |
| 手写痕迹 | 文档内每页的铅笔图标 → 涂抹擦除 → 局部像素修复 | 涂抹时稍覆盖笔迹边缘 |

**拍摄建议（能显著提升识别率）**
1. 纸放深色桌面，四角留空隙，避免与背景连成一片。
2. 手机尽量正对纸面，别斜着拍。
3. 光线均匀，避免半边亮半边暗和反光。
4. 文字材料用「黑白」滤镜 + 去阴影，OCR 效果最好。
5. 重要材料一页一页拍清楚，别贪多。

## 技术栈与已知边界

- Kotlin + Jetpack Compose + Material 3
- CameraX 1.3.4（相机在 App 内预览，不跳转系统相机）
- Tesseract4Android 4.9.0（Tesseract 5.5.1 引擎，chi_sim 中文离线）
- 纯 Kotlin 边缘检测（多点采样）/ Otsu 二值化 / 局部亮度归一化 / 涂抹式擦除，均不引 OpenCV
- AGP 8.5.2 / Kotlin 2.0.21 / Gradle 8.7 / JDK 17 / minSdk 26 / compileSdk 34（均在官方兼容矩阵内）

**边界说明**
- 边缘检测对「浅色文档 + 深色对比背景」效果最好；颜色接近时用手动/曲线模式。
- 黑白用全局 Otsu 阈值，光照极不均时不如专业 App 的局部自适应——这是为保持零依赖和速度做的取舍。
- 「曲线」模式提供四角手动校正；对页内局部波浪形起伏的精细展平能力有限。
- 清除手写是局部像素填充，笔迹覆盖面积很大时效果会打折。
- OCR 识别率取决于字迹清晰度和角度，重要材料建议先目视确认。
- 许可：Apache-2.0；Tesseract 引擎同为 Apache-2.0。
